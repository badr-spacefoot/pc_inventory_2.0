# Desktop collector and release audit — 2026-09-15

Scope: all `collectors/desktop_collector` modules, cross-platform inventory engine, Windows fallback script/build script, Windows installer, collector release workflow, release manifest and collector tests. Applied AAS `python-pro` and `security-auditor` guidance (catalog 16.1.0): data-flow review, error handling, privacy, release trust and testability. Source review and one isolated mock reproduction only: no hardware collection, installation, package execution, release publication or production submission. Parent audit owns full test execution.

## Decision

Existing collector source is reusable for the VPS deployment, but broad distribution is not ready without release trust controls and endpoint migration testing. A website DNS change cannot reconfigure previously installed binaries. The reported Defender incident remains undiagnosed: exact detection, affected artifact hash, actual signature and Defender result have not been supplied/verified. The findings below are not evidence that released binaries contain malware.

## Other coverage and observations

- Collection engine uses argument lists for subprocesses and bounded timeouts (`scripts/collect-cross-platform.py:62`); osquery hardware queries are static. Windows PowerShell fallback runs locally with `-ExecutionPolicy Bypass` (`:1242`), a behavior to review against endpoint policy, not proof of malicious activity. No dynamic user-controlled shell injection was established.
- Profile review and separate submit exist (`collector_app.py:1432`, `:1487`); scan includes hardware identity/serials, OS user, local IP and optional MAC. Desktop MAC inclusion defaults to true (`:304`), whereas PowerShell requires a switch. Align privacy copy, defaults and retention with the organization's intended policy. This audit does not certify legal compliance.
- TLS helper uses a validating default SSL context/certifi; no certificate-verification disable was found. HTTP allowance in COL-06 is separate from certificate verification.
- Windows installation requires administrator permissions and installs osquery (`installer/windows/spacefoot-collector.iss:24`, `:50`); collector reopens as original user (`:51`). Linux updater invokes sudo apt; macOS installs into user Applications. Document first-install admin needs and standard-user scan coverage; do not ask users to disable Defender.
- Current stale-widget mitigations check widget existence and suppress repeated callback dialogs (`ui.py:90`; `collector_app.py:335`; `diagnostics.py:18`). Background operations still schedule UI work without a general closing/cancellation guard; tests should close/rebuild UI while requests are pending. The error suppression does not prove every historical crash fixed.
- Diagnostics append to a per-user file, including exception text and paths (`diagnostics.py:34`, `:45`); no rotation or explicit redaction. No raw credential log was demonstrated. Add bounded retention and redaction before support exports; avoid asking users to publish full logs.
- Core inventory module is large (~1,340 lines) and UI entry is ~1,600 lines. Existing helper/mixin separation is a useful basis; targeted fixes are preferable to an unsolicited rewrite.
- `platform_integration.py:11` returns its own module path for unfrozen Linux registration, so source-mode protocol entry targets helper module instead of collector entry point. Packaged mode uses the executable correctly. Low-priority developer workflow defect.
- Tests reviewed cover normalization/version parsing, URL helpers, presentation/prefill application and diagnostics. They do not exercise actual installers/updaters, package rejection, delayed exception callbacks, network failure/cancel races, consent or supported OS matrix. Parent report records full suite results separately.

## VPS collector acceptance checklist

1. Choose canonical HTTPS API prefix under the controlled domain and preserve `/organization`, `/collect/prefill/{code}`, `/collect/access-token/validate`, `/collect/profile`, `/collect/scan` contracts.
2. Update defaults, website-generated links/downloaded prefills and future manifest URL together. Keep GitHub Pages legacy manifest serving an upgrade path; static GitHub redirect cannot be assumed to preserve POST/authorization for an API migration.
3. Publish a securely verified bridge release before retiring the old API. Test old binary with new deep link, new binary with old draft, every OS update/relaunch, expired tokens and rollback.
4. Test a real standard-user Windows installation with Defender/SmartScreen enabled and record version/hash/signature; test macOS 13.7.8 Intel and supported Apple Silicon, and defined Ubuntu minimum.
5. Establish owner, artifact retention/rollback, signing credential custody, dependency updates and incident/submission process. Do not substitute self-signed-certificate installation or quarantine removal for release trust.
